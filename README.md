# Antifraud Social Demo

Synthetic social-network relying-party demonstration. The preliminary portal
shows how a person reviews, authorizes, rejects and
verifies a request to sign an immutable publication manifest without exposing
private wallet material to React or to the relying party.

Start future work by reading
[`docs/USE_CASE_TASKS.md`](docs/USE_CASE_TASKS.md) and
[`.codex/skills/build-antifraud-social-demo/SKILL.md`](.codex/skills/build-antifraud-social-demo/SKILL.md),
then use the separately maintained Antifraud Data Space MVP Prompt v8 as the
complete implementation contract.

## Boundary

- This is a synthetic relying party, not a production social network.
- Authentication does not authorize a signature.
- A click, publication, delivery or read state is not a signature.
- React never creates or receives a seed, PIN, biometric value or private key.
- The BFF must reuse the reviewed high-level SDK and managed-wallet behavior.
- The demo must distinguish test, local-network, Test Network and production
  evidence.
- C2PA interoperability is a versioned adapter boundary; it is not proof that
  media content is true or was not generated by AI.

## Current status

Preliminary UI plus a local BFF and in-memory Fabric demo adapter. The demo
creates a server-owned immutable-manifest digest, supports authorization and
rejection, records a simulated receipt and reloads it through the BFF. The
receipt explicitly carries `cryptographicProof: false` and is not a wallet
signature, Fabric transaction, local-network result or Test Network result.

Run with Node.js 24:

```bash
npm ci
ANTIFRAUD_SOCIAL_DEMO_MODE=true npm run dev
```

The synthetic demo PIN is `0426`. It is a public fixture and never represents
production authentication or wallet protection.
